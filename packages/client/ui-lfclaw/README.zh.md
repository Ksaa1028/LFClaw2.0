# LFClaw 员工专家助手

[English](README.md) | 中文

## 概述

员工可在“企业专家”“我的专家”“我的专家团”三个页签中查找资源。创建和修改直接进入带“专家管理”技能引用的新对话，在聊天中补全需求并保存配置。使用专家时先检查实时授权和本机依赖，再准备任务对话；个人配置仅本人可读写。

输入框的专家和专家团使用轻量 `employee/expert-picker` 列表。选择时在本机追加引用，按原文顺序保留草稿，不请求完整配置。发送时解析当前授权指令及依赖；授权撤回后阻止提交。

<a id="usage"></a>
## 使用

专家页面读取 `employee/expert-catalog`，保留完整专家说明、快捷提问和团队成员，关联技能及连接器只读取标识和名称，不下载无关图标、模型配置和通知。详情无需再次请求；启动专家仍校验当前权限和依赖。

专家页面及输入框中的专家、专家团选择器复用当前员工的 Host 目录快照；Host 参数 `expertCatalogMaxAgeMs` 控制最长展示复用时间，默认 30000 毫秒，设为 0 可禁用。手动刷新、专家准备及执行始终请求最新服务端状态。个人专家和专家团的创建、修改及删除使旧目录失效；换账号、注销和同步失败沿用企业连接服务的快照清理规则。

专家页面固定标题、页签和搜索栏，仅卡片区域滚动。消息通知固定标题和页签，公告与会话分享各按每页 10 条展示，翻页控件固定。切换消息页签后回到第一页。

LFClaw 的侧栏名称、侧栏图标与对话品牌图标以优先级 `-1` 覆盖默认优先级 `0` 的品牌贡献；两者可同时加载，卸载 LFClaw 插件后恢复默认品牌。侧栏名称由 LFClaw 字典提供，不能只替换图标而保留默认文字标识。

桌面组合装载本插件；企业 Web 预览的覆盖文件同时启用员工激活、技能、连接器与专家助手。Host 依赖 `connection`、`enterpriseConnection`、`skills`、`tools`；Client 依赖 `slots`、`locale`、`layout`、`uiWorkspace`。Host 的 `sharedSessionDirectory` 指定已领取分享输出文件的本机持久目录，插件默认使用用户主目录下 `.lfclaw/shared-sessions`，桌面组合将其设为当前 DSH 主目录下 `lfclaw/shared-sessions`；Client 的 `shareRefreshIntervalMs` 指定分享通知刷新间隔，默认 30000 毫秒，最小 1000 毫秒。

<a id="workflows"></a>
## 工作流转

员工入口与面板目前隐藏，保留实现和服务端已有记录。

发起时先对话：AI 整理标题、需求、验收标准和交接摘要，识别明确指定的人员并追问缺项；员工核对工作卡后确认指派。详细字段仍可编辑，完结抄送支持姓名搜索、部门筛选与勾选。在页面保持挂载期间返回列表保留未提交草稿；发起成功后回到“我发起的”。后续操作未填写摘要时可根据处理说明自动生成交接摘要。

侧栏“工作流转”支持部门内与跨部门协作：确认需求、指定单个处理人、补充、转交、提交、打回、验收和完结抄送。发起人选择验收人与完结抄送人。需求变更保留快照，处理人确认后才能继续；发起人取消时保留记录。

每次操作必须填写原始说明与交接摘要。AI 整理输入文字并列出缺失需求，不读取上传文件，也不代替验收；员工确认建议或手工填写摘要。文件按提交版本保留；HTTP/HTTPS 链接由外部系统管理，内容可能变化。完结抄送只展示最终提交与验收记录，参与人可查看完整历史。

企业服务持久化记录、校验当前身份与节点负责人，并拒绝过期版本。完全相同的请求通过操作标识安全重试；修改已提交请求前须先核对记录。请求失败保留输入。列表打开时沿用 shareRefreshIntervalMs 刷新。服务器 workflowRequestMaxBytes 限制含 Base64 附件的整个 JSON 请求，默认 4194304 字节；大文件请使用共享链接。

MVP 使用串行处理与人工指派，不包含并行会签、自由流程设计器或自动升级催办。管理员只能查看元数据列表，不能参与处理。管理员可下载备份不包含工作流正文；运维文件级备份必须保留完整数据库。

<a id="session-sharing"></a>
## 会话分享

“消息通知”分为“企业公告”和“同事分享”两个标签，仅展示当前类别的消息和未读数量；侧栏角标汇总两类未读。卡片不重复显示所属分类；同事分享卡片保留发送者姓名以区分来源。未读消息使用浅色卡片和“未读”标识，已读消息显示“已读”标识；只有未读消息提供“标为已读”操作。企业公告不提供删除或清空入口；同事分享消息可在确认弹窗中单条删除，已领取的本机会话不受影响。管理员发布公告后，页面展示标题、正文和发布时间。公告状态由企业服务按员工保存。管理员撤回公告后，服务端不再向员工返回该消息；已打开的客户端在下一次收件箱轮询或手动刷新后移除消息并更新未读数。当前打开的桌面程序须装入更新后的 Host 与 Client 插件，才会显示公告；旧程序不会因服务端单独更新而新增入口。

历史会话菜单的“分享会话”支持搜索全企业有效员工并跨部门多选。发送完整会话日志、持久附件及 `deliverables/presented` 声明的 AI 输出文件；缺失文件、读取失败或超限均拒绝发送。员工凭据由 Host 保管。服务器保存文件副本后，接收人的“同事分享”标签显示来源、标题、时间和过期状态，未读数量随在线刷新同步。

领取会话复制附件和输出文件，重定位历史输出路径，以独立 ID 建立本机继承会话，并使用接收人的默认 Agent 预设和模型。父会话 ID 指向来源会话，确保继承的投递回执能够回读。原会话不被改写；DSH 的继承分界区分原始历史与接收人新增内容。重复领取返回同一本机会话，已领取的文件不依赖服务器分享继续存在。后续连接器调用沿用接收人的企业身份及实时授权。

删除或清空消息只修改接收人的通知，不删除分享文件或本地会话。下载失败保留消息；发送时网络中断可能导致结果未知，需接收人核对消息后再操作。领取期间的存储失败可能留下未被会话引用的附件及输出文件；不自动删除用户的持久目录。分享预设、工具代码与企业凭据不会安装到接收人环境。

侧栏和页面标题均为“专家助手”，页面布局、搜索框、卡片和详情弹窗沿用技能管理样式。“我的专家”提供“创建专家”，“我的专家团”提供“创建专家团”；详情的“对话修改”携带本人资源 ID 打开专家管理技能。员工端没有创建和编辑表单。“刷新列表”重新读取当前员工可见资源。

专家管理支持自然语言需求与资料转化，整理角色、工作方法、输出规范和依赖后通过工具保存。修改前读取当前修订摘要，冲突时拒绝覆盖。企业专家由管理员维护，员工不能用个人管理工具发布企业资源。

<a id="implementation-and-failures"></a>
## 实现与失败

专家助手复用 Host 的员工持久登录，浏览器不持有企业令牌。本地 `/api/lfclaw/expert-center` 读取目录，`expert-prepare` 准备任务定义，`personal-experts` 执行本人删除。对话管理工具直接使用 Host 企业传输读取和保存本人配置。个人配置同步到企业服务；管理员列表和企业备份排除其内容。

保存时校验成员属于本人、成员不是专家团、技能和连接器当前有权使用；启动时再次检查专家、成员和全部成员依赖。客户端随后检查本机技能就绪状态和连接器已授权工具目录。任一失败保留原任务并报告错误；工具实际执行仍重新鉴权。网络中断导致保存结果未知时要求读取列表核对，不盲目重建。

已有配置省略扩展字段时按单专家读取。删除成员会令引用它的个人专家团无法准备任务，直至重新配置。查看和创建入口不会发送模型请求；用户发送后沿用标准会话记录与技能注入链路。

相关接口见[企业服务](../../../LFClaw/02-管理端/server/README.zh.md)，WorkBuddy 参考原包与适配资源见[专家管理资源](../../../LFClaw/09-资源/技能/专家管理/README.zh.md)。

<a id="model-experience"></a>
## 模型体验

### 专家管理技能与工具

#### 模型看到什么

显式技能引用加载 `lfclaw-expert-manager` 的正文。`list_expert_resources` 返回本人专家和已授权企业能力，`read_personal_expert` 返回完整配置与修订，`save_personal_expert` 创建单专家或修改已有配置，`create_personal_expert_team` 一次创建专家团和缺少的成员。成员无需预建：读取已有成员完整配置后决定复用，新成员在同一对话设计，服务端整组校验并保存；失败不留下部分新成员，不修改复用成员。工具 schema 描述字段限制；结果保留实际 ID 和名称。失败通过标准工具结果报告，不能把文字承诺当作保存成功。

#### Token 影响

技能正文仅在加载后进入会话；四个工具的参数说明与可见工具一起进入请求。读取完整配置、目录和后续工具结果分别占用上下文，随实际专家数量与指令长度变化。

#### KV Cache 影响

已发送的技能与工具结果沿用普通会话历史；修改配置不改写历史消息，后续重新读取会增加新结果。没有额外的隐藏系统提示词更新。

### 专家任务与团队委派

#### 模型看到什么

准备的草稿含简洁专家引用与任务；发送时引用序列化读取当前授权配置、检查本机依赖，并把完整指令、成员配置及技能调用文本纳入本次消息。用户发送后，单专家按其指令工作；专家团提示要求主理人通过实际 `subagent` 工具派发独立任务，记录真实子代理 ID，等待真实结果，再汇总。独立的约束审阅可与方案设计并行；依赖草案的审阅等待草案，普通排版和汇总由主理人完成。子代理只在最终答复回传一次；主理人等待成员时不重复查询状态或运行休眠命令，收到所有成员结果后只交付一次。最终答复优先完成用户要求，压缩内部过程，为字数上限预留余量。未派发成员须说明，工具缺失时明确停止，不允许模拟成员产出。任务提示要求遵守完成标准与字数上限；排程时核对工时、时段、截止时间及依赖，不能凭空缩时或延期，也不能为了计数字数反复创建临时文件。

#### Token 影响

任务配置作为用户输入进入会话，成员数量和指令长度决定输入成本。子代理独立请求与结果回传产生各自 Token 消耗，不因“专家团”展示而免费复用。

#### KV Cache 影响

专家配置在发送时读取并记录；编辑草稿期间修改专家会影响该草稿后续发送时加载的配置。不同子代理使用各自会话历史，主理人收到的结果追加到主会话，不保证跨成员共享缓存。

## 已知限制与待完成工作

<a id="known-limitations-and-deferred-work"></a>

- 子代理工具来自所选预设；实际执行结果取决于模型和成员配置。专家团提示可以要求核对约束与等待真实结果，但不能保证模型输出正确或在固定时间内完成。
- 已授权的百炼、Dify Chatbot / Chatflow 和 WeKnora Agent 专家可从专家助手详情或输入框“专家”选择器进入普通会话；发送前先检查本机远程专家工具是否已加载，未加载时停止并提示重启。发送后模型须调用 `call_enterprise_expert`，由 Host 使用员工身份转发到企业服务，答复作为工具结果记录。尚无服务端对话适配器的其他外部平台仍只展示目录和接入提示；含外部服务成员的专家团尚未支持。
- 专家依赖选择当前限企业技能和连接器；个人能力依赖、完整专家 ZIP 导入导出、头像生成、版本回退尚未接入。
- WorkBuddy 原包作为参考保留，不执行其目录写入和注册脚本。资源中的适配 ZIP 是管理技能，依赖本插件提供的工具，不能独立实现专家管理。

个人专家的服务端响应可包含 `source: personal`。详情使用企业归属与明确的外部来源共同判断远端专家，个人专家和个人专家团均提供本机任务入口。

个人专家卡片仅展示名称、简介与详情入口，不重复展示归属和类型标记；类型仍可通过图标与筛选识别。企业专家卡片展示来源（原创、阿里云百炼、Dify、WeKnora 或外部平台）。详情不再常驻显示通用的依赖权限说明，实际失败仍报告具体原因。

专家使用入口准备简洁引用，发送时展开的配置以“本次使用专家：名称”或“本次使用专家团：名称”开头，随后携带完整配置，发送后可从消息记录核对。提示要求回复开头注明名称，但名称不代替真实委派记录；专家团成员参与仍以实际子代理调用及结果为依据。直接在普通会话粘贴任务不会自动选择专家。

输入框加号菜单提供“专家”和“专家团”两个选择入口，分别按“企业专家 / 我的专家”和“企业专家团 / 我的专家团”分组，可跨组搜索已授权企业原创资源、已接通服务端调用的百炼、Dify 与 WeKnora 专家及本人的个人资源；其他外部来源需先配置对话适配器。选择时重新校验授权和本机依赖，把简洁专家引用加入当前会话草稿，保留原任务、引用与附件，不自动发送或另开会话。加载期间草稿修改或会话释放会阻止覆盖，提示重新选择。

发送后的专家引用默认折叠为名称，点击名称展开完整工作配置。完整配置以带名称的结构化文本保留在消息记录中，模型输入和回放仍可重建；仅改变显示。缺少结构标记的旧消息不按关键词猜测折叠，格式无效的标记原样显示。

专家团运行区分持久团队与临时子代理。持久团队通过 spawn_teammate 返回的目标进行团队通信；subagent 返回的临时会话 ID 不属于团队 send_message 的地址空间，也不能用团队 list_agents 查询其状态。临时结果等待系统回传，成员失败后报告具体阶段并停止自动重复派发。

专家引用跟在用户任务之后，保留用户文字与既有引用的位置，使会话标题取任务内容而非内部配置包。发送时仍读取完整配置；所需技能的调用标识保留为独立文本，供现有技能加载器识别，不藏入JSON转义字符串。

<a id="dev-note"></a>
### 开发备注

专家任务使用现有会话、技能与子代理机制，企业服务负责实时资源授权。
