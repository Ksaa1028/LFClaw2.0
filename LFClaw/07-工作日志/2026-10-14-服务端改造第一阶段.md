# 2026-10-14 服务端改造第一阶段

## 目标与依据

根据最新指令，以 DSH 为底座重新实现 LFClaw 企业服务，不复用旧企业后端。商场 MCP 源码位于 `E:\code\lf-mcp-server2`，本阶段只核对协议与实现，没有修改该仓库。先做管理身份、员工激活、资源授权和模型网关的基本服务端链路，客户端留到服务端完成后接入。

## 已修改

- 将原独立 Express 入口改成 Cordis 插件，通过 `dsh web --patch LFClaw/02-管理端/server/cordis.patch.yml` 注册 `/lfclaw/api`。当前 overlay 暂停尚不存在的 `ui-lfclaw` 行，以便先验证服务端；管理员前端开发代理转向 DSH Web。
- 新建管理员密码哈希、持久化会话令牌摘要、员工激活和重置失效；停用拒绝请求，重新启用后未重置的登录可恢复。数据读写改为校验后原子替换，损坏文件保留原件。
- 企业模型密钥留在服务端，管理返回值脱敏；员工只能访问当前授权且启用的模型，模型调用由服务端转发。部门、员工、模型、技能、连接器、专家的管理页面开始对接真实 API；通知发布由服务端保存并供员工读取。
- 限制通用写接口仅修改上述六类资源，避免把伪备份、伪版本和伪日志写入数据库。技能 ZIP 上传加入大小、条目数和基础 `SKILL.md` 检查。本地数据目录加入 `.gitignore`。
- 核对商场 MCP 的断言字段、HMAC-SHA256、有效期与权限名称；新增服务端楼层/自营权限计算和签名函数。尚未建立 MCP SSE 代理及真实工具联调。
- 员工激活码改为 `LF-姓名拼音大写-8位随机码`；现有旧码保持有效直到管理员重置。
- 完成企业数据和技能附件的手动 ZIP 备份、下载、上传校验恢复及恢复前安全备份，管理页已接入真实接口；版本页未接服务时禁用原型按钮，避免误报发布成功。
- 员工资源接口改为逐字段投影；连接器只下发已允许的工具，模型、连接器和专家的服务端凭据不进入员工响应，账户接口返回本人激活码。
- 管理员增删改和激活码重置写入脱敏操作日志；模型调用先写入待完成用量记录，随后保存员工、部门、模型和服务商返回的 Token。尚无可信价格时费用状态记为“未获取”，不写伪 0。
- 商场 MCP 新增旧版 SSE 客户端桥接：管理员维护连接地址并测试/发现工具；员工调用由服务端按当前授权校验连接器与工具，再签名楼层权限断言。缺少共享密钥时明确返回未配置，真实 MCP 服务尚未联调。
- 管理员新增修改密码入口与服务端接口，修改后旧管理员会话失效，员工会话保留；旧密码错误返回 401。预览服务重启后通过开发代理验证了错误密码路径。
- 系统状态页改为读取当前主机 CPU、内存、数据盘占用，支持手动刷新；磁盘读取失败显示未获取，网关可应答时标记在线。预览环境下新接口返回 200，四项指标均有真实值。
- 员工资源授权改为统一计算：部门范围向下继承，资源可为单个员工设置允许、拒绝或恢复继承；管理员可查询每项资源的生效来源。员工资源列表、模型调用及商场 MCP 工具调用在请求时重新校验，撤权即时生效。授权变更写入操作日志。本步服务端测试与类型检查通过，管理页的授权编辑控件仍待接入。
- 管理页员工列表补上“查看详情”入口，详情改为读取服务端生效权限，并可对四类资源设置个人允许、拒绝或继承；显示停用、未授权、部门继承等来源。管理页类型检查通过，预览首页和模块加载返回 200。浏览器当前停在登录页，尚未完成已登录页面的视觉验收。
- 修正手动备份恢复遗漏模型用量的问题；在创建恢复前安全备份之前验证归档数据库结构，恢复后只登记真实存在的安全备份，避免旧备份列表指向不存在的 ZIP。新增回归测试：模型用量恢复、无效数据库不改动原文件；服务端 4 个测试与类型检查通过。
- 修正模型编辑时把原部门/员工授权范围重置为全员的问题；新建或切换默认模型时，服务端与管理页同时清除其他默认标记，避免界面和数据出现多个默认模型。服务端测试与前后端类型检查通过。
- 增加独立的上游模型 ID 配置；服务端转发使用该 ID，管理页名称只作展示。旧记录未设置上游 ID 时继续按旧名称调用。测试确认转发给上游的 ID 与展示名称不同，前后端类型检查通过。

- 管理员登录与员工激活新增按来源地址分别计数的失败尝试限制，阈值和窗口由 Cordis 配置控制；超限返回 429 与 `Retry-After`，成功后清零。测试覆盖两条链路且服务端类型检查通过。限制当前为进程内状态，重启后清空。
