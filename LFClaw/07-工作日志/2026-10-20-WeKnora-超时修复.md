# WeKnora 复杂请求超时

## 问题

管理员配置的 WeKnora 专家可完成简短请求，但一次人员综合分析调用返回“远程专家暂不可用”，随后重试成功。本机企业服务日志记录 `The operation was aborted due to timeout`。当时 `expertTimeoutMs` 为 60 秒；同一个截止时间覆盖创建远程会话、发送问题与读取完整事件流。失败时服务端把超时当作通用平台故障返回。

## 修改

- 本地企业服务的远程专家总等待时间由 60 秒调为 180 秒，仍保留有限截止时间。
- WeKnora 只在收到 `complete` 且有正式回答时返回结果；截止时间到达后丢弃未完成的答复，以 `WeKnoraTimeoutError` 标识失败。
- 员工调用和管理员测试将该失败返回 HTTP 504 与 `EXPERT_TIMEOUT`，不再提示检查地址或接口权限。远程平台可能继续处理超时请求，重试可能创建另一会话。

## 验证

- 本机数据中的 WeKnora 专家以简短问题进行真实调用，约 2.4 秒得到正式答复；未输出或记录空间密钥及答复正文。
- `pnpm --dir LFClaw/02-管理端/server exec tsx --test tests/weknora.test.ts tests/server.test.ts`：7 项通过，覆盖超时分类和 HTTP 504。
- `pnpm --dir LFClaw/02-管理端/server run typecheck`：通过。
- 本机企业服务已重启，健康接口返回 HTTP 200；再次用简短问题调用 WeKnora，约 3.4 秒得到正式答复。

## 后续

原复杂问题未重复发送。若同类问题在 180 秒后仍超时，记录发生阶段与 WeKnora 侧耗时，并按实际需要调整 `expertTimeoutMs`。
