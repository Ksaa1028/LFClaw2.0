# 首页文案配置

管理端“系统状态 → 首页文案”支持修改员工端首页口号、标签文字与显示开关，并提供文字预览。默认口号为“让想法落地，让工作轻松”。服务端仅允许管理员保存，公开读取仅返回品牌信息；配置随数据库持久化及手动备份恢复，旧数据缺少字段时补用默认值，非法数据拒绝读取。

员工端通过本机 Host 读取配置，在首页挂载和窗口获得焦点时更新。请求失败保留上次成功文案并提供重试，不影响聊天。通用会话界面提供 `conversation.hero.brand.text` 插槽；没有贡献者时保留语言词典文案。首页内容不进入模型请求和会话日志。

验证：企业服务 `pnpm --filter @deepseek-ai/lfclaw-admin-server test` 9 项通过，涵盖保存鉴权、长度和格式校验、重新读取、备份恢复及旧数据默认值。管理端和企业服务 typecheck、管理端 build 通过；客户端首页与 Host 文案读取测试 7 项通过，会话 skeleton 测试 26 项通过。针对 ui-lfclaw 与 ui-activation Host 的 TypeScript 构建通过，三个相关插件分别 bundle 通过。多包一起 bundle 遇到工作区依赖环，改为分别构建成功。

完整 `pnpm run doc-sync` 未通过：工作区已有测试引用未列入 Host 项目、RequestInit 目录分类、src 下遗留声明重复、文档链接与双语配对等错误。ui-conversation README 中英文补充并重新记录配对。初次品牌测试遇到同时进行的图标改动，本次未覆盖图标文件或重写其快照。

浏览器检查停留在管理端登录页，未进行登录后真实页面验收。未重启已有服务，未重新打包或安装桌面应用；部署需更新企业服务与客户端插件并重启相应进程，之后验证管理端保存及桌面端刷新显示。

后续运行修复：用户反馈管理端“文案加载失败”。实际请求发现 39811 上旧企业服务返回 `Cannot GET /api/branding`（404）。已使用原 `server/data/live` 数据目录和相同 dsh Web profile 参数重启企业服务，未修改管理员凭据。后端直连及经 5173 管理页面代理读取 `/lfclaw/api/branding` 均返回 200 与默认文案；未登录管理员配置接口返回 401。现有用户可点击文案区“刷新”重新读取；本次未持有管理员登录态，未声称亲测登录后保存。

桌面端同步修复：用户保存口号并关闭标签后，服务器配置正确，桌面仍显示原词典文案。根因是文案插槽贡献者原属桌面默认停用的 ui-lfclaw 专家插件。现已将组件、词典、注册及测试移至桌面启用的 ui-activation 插件，保留专家插件停用状态。激活插件单独装载即可展示配置，焦点刷新、标签隐藏及失败重试测试通过（本轮两个测试文件共 7 项），相关 TypeScript 构建及两个插件 bundle 通过。

运行验证：通过受支持的 start:desktop 启动器重启开发桌面，保留原 home 与 Electron 用户目录。在同一桌面 Host 的浏览器界面实际读到首页“让想法落地，让工作轻松”，页面未显示预览版标签，员工登录态与原会话列表仍在。
