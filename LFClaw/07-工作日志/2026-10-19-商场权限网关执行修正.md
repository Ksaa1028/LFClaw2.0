# 2026-10-19 商场权限网关执行修正

## 目标与范围

根据用户补充要求，完整五项楼层权限允许调用已分配且已启用的淘气堡及未知工具；MCP 代码和配置均不修改，也不要求用户配置共享签名密钥。本记录取代同日《商场 MCP 权限对接》中关于签名密钥前提及未知工具一律禁止的结论。

## 实际修改

- LFClaw 通过现有普通 MCP 接口调用，移除签名探测及共享密钥依赖。原有 `mcpSecretEnv` 配置项仅为兼容旧配置保留，不再读取对应环境变量。管理端保存和测试连接器时验证实际连接与工具发现。
- 有效权限包含一层、二层、三层、四层、自营全部五项时，允许所有已分配且已启用的工具，包括淘气堡和未知工具；无楼层权限时不允许商场工具调用。
- 部分权限仅开放已审计的楼层、区域、店铺三个查询工具。显式越界参数整次拒绝，省略楼层时由网关填入授权范围；按单楼层拆分调用，避免上游返回全场汇总。身份参数由网关覆盖，员工或模型不能指定上游身份。
- 保留授权提交通知、目录长轮询、旧工具注销、在途请求取消和响应返回前复核。拆分调用期间每次调用前后也检查当前权限；权限变化后迟到结果不能作为旧授权结果返回。
- 更新管理端提示、服务端说明、客户端中英文说明及升级指南，新增完整权限调用淘气堡的正式 profile 会话回放。

这些限制作用于经过 LFClaw 企业网关的调用。其他客户端直接访问 MCP 的既有行为不受此次修改影响。
