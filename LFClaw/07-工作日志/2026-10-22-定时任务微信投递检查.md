# 定时任务微信投递检查

用户报告普通会话创建每日任务后，模型称没有微信消息渠道。本次只读检查，没有创建、删除或修改定时任务，没有向外部渠道发送消息，也没有迁移账号凭据。

定时服务将到期提示注入创建任务的原 Session，deliveryMode 为 host 表示宿主驱动执行，不单独决定结果是否发往 IM。现有 dsh-im-connect 按 Session 与渠道聊天的映射监听助手消息；有映射且渠道可用时尝试投递，普通网页 Session 没有映射时不投递。插件没有为普通会话注册可指定微信收件人的模型发送工具。

实测当前本地开发客户端 GET /api/dsh-im-connect/channels 返回微信未配置、账号数为 0；默认用户数据目录另有一个启用且接收开启的微信账号配置。两套 Harness home 的账号数据独立，不能把另一个目录的保存状态当作当前客户端已连接。检查的两处定时存储中未找到截图任务，未确认其实际创建位置或后续触发结果。

微信适配器发送使用入站消息保存的 context_token；插件说明明确微信补发等待原聊天新消息刷新回复通道，并受连接、时效和配额限制。因此微信绑定会话的普通回信与长期无人交互的每日主动推送是不同的验收项目。不能根据插件能回信便承诺次日定时主动送达，也不能仅根据技能和企业连接器清单断言所有 IM 渠道都不存在。
