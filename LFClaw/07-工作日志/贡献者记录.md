## Handoff notes

- The admin web app is a service-side/B-side management app. It must not be described as the employee client.
- The employee client needs local workspace selection and local filesystem behavior. A deployed web app can only select folders visible to the server process.
- `apps/admin-web/src/mock/data.ts` currently owns prototype data for departments, employees, approvals, billing, versions, backups, system status, and logs. Replace each dataset module-by-module with real backend APIs before calling the module production-ready.
- `apps/admin-web/src/pages/NotificationsPage.tsx` still has local `HISTORY` fixture data inside the page. Move it behind the same data/API layer when polishing the notification module.
- Generated files under `packages/client/ui-workspace/src/client/**/*.js`, `*.d.ts`, and `*.map` were observed as untracked build outputs and should be removed before commit.
- `apps/admin-web/lib/` was observed as stale generated output from the admin app and should be removed before commit.
- Use `LFClaw/` as the product entry folder. The repository root remains the DSH engineering workspace and should not be flattened below its build-required folders.
