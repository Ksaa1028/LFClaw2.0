# 2026-10-16 自动压缩与输出续接

复用 compaction-basic 的提前压缩及上下文超限恢复，standard、ptc、cordis 三个实际会话预设显式启用 80% 阈值、4096 token 余量、16% 近期保留和 4096 token 摘要上限。企业激活插件通过现有轮次扩展点实现输出截断后的同 Session 自动续接，不修改 agent-loop。默认每个人工请求最多续接 3 次，连续 2 次空文本或相同文本且无成功工具结果时停止；接口失败不进入输出续接，沿用部署的有限重试。用户新消息优先，取消与卸载清理待执行的自动提示。

续接指令、次数与提示来源写入 Session，新增独立来源的兼容记录已生成，现有记录仍可读取。自动续接依赖模型根据已有记录继续，插件不重放工具，但不承诺模型永远不会再次请求同一操作；最大次数限制不同措辞的无效循环。

验证：激活与压缩相关 135 项测试通过，其中自动续接 12 项覆盖恢复次数与非法排队输入；另有 3 项实际预设配置检查通过，确认旧的 32K 模型具有有效压缩预算；本包的输出期望快照回放通过。Host / Client 叶项目 TypeScript 检查通过，持久化类型校验通过（63 个根、15 条历史记录）。

全仓 doc-sync 为 25 通过、18 失败，涉及已有文档类型漂移、生成目录、未登记路径与导出文档问题。Host 聚合检查仍因企业连接器和模型网关测试文件不在项目文件列表而失败；本次续接源码没有出现在末次聚合错误中。尝试新增真实 SDK 启动回放时，运行时仍使用 DeepSeek 路由并因 MISSING_CREDENTIAL 结束，随后等待第二轮超时；未保留未通过的新增场景，真实 SDK 启动路径尚未验证成功。未部署运行服务、未打包安装器、未进行真实模型调用。
