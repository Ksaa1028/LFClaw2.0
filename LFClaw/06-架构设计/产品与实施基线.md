# LFClaw 产品与实施基线

## 摘要

LFClaw 以 DSH 为底层，交付企业管理 Web 与员工桌面应用。企业服务器统一管理身份、授权、企业资源和模型调用；员工设备运行 DSH Agent，保存本地会话与文件。本文是需求解释与实施约束参考，不代表功能已完成。

## 需求依据

产品行为以用户最新明确要求及[原始需求](../03-需求文档/LFClaw_需求_提取.txt)为依据；[PRD](../03-需求文档/LFClaw_PRD.md)用于页面梳理，[架构方案](LFClaw_Architecture.md)属于待源码核对的实现设计。两者与原始需求冲突时，不将额外功能自动纳入范围。DSH 扩展遵循[底层架构](../../docs/architecture.md)，支持的 Node 应用通过 dsh profile 组合启动。

已发现的冲突：模块计划包含审批和配额，原始需求没有审批模块且明确不做配额；PRD 提及备份设置，原始需求仅允许手动备份；架构方案将会话元数据笼统放到服务端，而原始需求要求聊天本地保存，仅按明确例外上传；方案声称 ui-lfclaw 已存在，但本次目录核对未找到该包。以上不得作为已实现能力或新增需求的依据。

## 两端职责

| 区域 | 目标职责 | 数据与权限要求 |
|---|---|---|
| 企业管理 Web 与后端 | 单超级管理员、部门员工、激活码、企业资源授权、模型网关、计量、版本、手动备份与基础运行状态 | 服务端校验身份和有效授权，企业 API Key 不下发员工端 |
| 员工桌面端 | 激活后进入聊天，使用授权模型、技能、连接器、专家及个人扩展 | Windows x64、macOS Apple Silicon；复用 DSH 会话、文件、插件与调度能力 |
| 本地执行 | 聊天、工作文件、定时任务和个人微信/飞书 Agent | 电脑与 Host 未运行时不承诺执行；管理员只看允许上报的任务元数据 |
| 例外同步 | 个人专家配置、企业资源、分享通知 | 个人技能和插件不自动跨设备同步；管理员不查看个人专家、聊天正文或个人凭据 |
| 会话分享 | 跨部门分享完整会话与附件，接收后在本机独立继续 | 后端磁盘临时保存，默认 30 天、50MB，可配置；新工具调用按接收人权限 |
| 客户端发布 | 双平台独立版本、普通或强制更新、版本上报 | OSS 分发安装包，升级保留本地数据，不能以 OSS 替代分享磁盘 |

身份链路必须区分停用、重新启用、重置激活码和单设备退出。停用拒绝新请求；重新启用恢复仍有效的登录；重置使旧凭据在所有设备失效；退出只影响本机。授权变更在服务端立即约束新请求，客户端在线刷新，资源更新不得任意中断已有任务。

知识库权限与商场 MCP 行级权限等待真实接口和源码核查。明确不做复杂 RBAC、积分配额、个人长期记忆、自研知识库、自动备份、服务器代跑员工任务、统一 IM 机器人及独立故障诊断平台。

## 必要配置与界面

| 配置归属 | 必须保留的内容 |
|---|---|
| 管理员身份与组织 | 登录、退出、修改密码、安全管理命令重置；部门关系、员工状态、激活码重置、授权来源与个人覆盖 |
| 模型 | 模型 ID、展示名、协议、Base URL、服务端密钥、启停、测试、默认模型、授权、计价单位与币种 |
| 企业能力 | 技能 ZIP 校验、SKILL.md、版本回滚；连接器接入参数与工具授权；专家类型与 API 参数；企业插件版本、配置与发布 |
| 分享与发布 | 分享保留时间和体积上限；平台、版本、安装包、说明、普通/强制更新；手动备份与恢复校验 |
| 员工端 | 激活码、授权模型选择、个人连接器绑定、个人技能/专家/插件配置、本地任务规则与状态、账号退出 |
| 部署 | 预置企业服务器地址、密钥存储、数据目录、网络与更新配置；部署变化项不得散落硬编码 |

界面保持精简，将高频操作直接展示，将低频配置放入详情或所属模块。简化不能删除必要配置、权限来源、加载状态、空状态、失败信息及恢复操作。费用无法获得时显示“未获取”，不能以 0 代替。

视觉参考优先使用 [01_Current](../04-UI设计/01_Current/)；[早期概念](../04-UI设计/02_Earlier_Concepts/)仅供对比。现有文字说明称管理端深色侧栏，但已查看的当前管理端图使用浅色侧栏，需在实际设计时统一；图片不决定权限与业务行为。

用户要求后续 UI 设计使用 image-2 辅助美观控制。执行时先确认可用工具能否指定该模型，不能将其他模型输出称为 image-2。设计稿用于布局与风格校准，成品仍需在真实页面检查中文、间距、对比度、缩放、键盘操作与各交互状态；本次未生成或修改 UI。

## 实施与验收

按依赖顺序推进：先修复启动与数据安全基础，再打通“管理员建员工 → 激活 → 授权模型 → 网关真实调用 → 撤权拒绝”的最小闭环；随后接入连接器、企业能力分发、专家、本地任务、分享通知，最后完成 IM 与双平台发布。现有实现缺口见[本次核对记录](../07-工作日志/2026-10-14-项目理解与现状核对.md)。

每个模块分别记录界面、真实接口、持久化和验收结果。测试覆盖正常操作及相关失败场景，重点包括未登录/越权、停用/重置、网络失败、重复操作、数据损坏、重启后数据保留及更新失败恢复。按仓库要求补充行为测试、必要快照和发布路径验证；第三方接入与双平台安装需要各自真实环境证据。

“不能有 BUG”落实为缺陷修复和可重复验收要求。不能承诺绝对零缺陷，也不能凭按钮可点击或编译成功宣称稳定；发布前关闭已知阻断缺陷并列出未验证项目。

## 维护与交付

维护沟通、新增 LFClaw 文档、工作记录和面向维护者的说明使用中文；协议标识、包名和必要技术名保持原样。保留 DSH 的工程目录与扩展机制，不为整理而打散构建结构。

每个实质阶段及时记录日期、目标、实际修改、验证命令及结果、遗留问题和下一步。区分本次亲测与历史报告，不记录密码、令牌、企业密钥或业务数据。历史记录中的结论不能替代当前源码与测试证据。

用户提供新 Git 地址且项目达到约定验收标准后，再整理提交与上传。交付前核对依赖和锁文件、构建产物、测试数据、敏感信息、文档链接、部署配置示例、版本映射及恢复说明；当前不更换远端或推送。
