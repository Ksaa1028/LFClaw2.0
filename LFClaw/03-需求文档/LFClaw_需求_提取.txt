01｜项目目标与总体原则
1.1 项目定位
LFClaw 是面向商场企业员工的 AI 桌面工作平台。员工通过 Windows 或 Apple Silicon macOS 客户端，使用企业授权的模型、技能、连接器与专家，同时保留个人技能、个人专家、个人 Cordis 插件的扩展能力；管理员通过既有 LFClaw 后台统一配置员工、授权、客户端版本和使用统计。
1.2 项目原则
•  以 DeepSeek Harness（DSH）为桌面 Agent 运行基础；以现有 LFClaw 企业后端为管理基础，避免重复开发已有能力。
•  普通员工开箱即用：安装包内预配置服务端地址；首次启动直接使用激活码；隐藏复杂企业技术参数。
•  企业资源由管理员统一发布及授权，员工个人资源允许独立扩展；企业核心数据权限必须由服务端执行。
•  默认本地优先：聊天、工作文件、定时任务与 IM Agent 执行位于员工设备；明确批准的服务端数据例外见后文。
•  维护独立 LFClaw 分支和版本基线，选择性适配 DSH 上游更新；不直接覆盖已完成的企业定制。
•  先验证核心链路，再逐步实施；不以第三方仓库 README 代替在 Windows / macOS 上的实际验收。

03｜完整功能需求
功能 01｜员工激活与登录（已确认）
•  管理员创建员工后自动生成永久激活码，格式为 LF-员工姓名拼音大写-8 位随机码（例：LF-TONGKAI-XXXXXXXX）；激活码默认不过期，后台可启用/停用。
•  员工首次启动客户端输入激活码，联网完成服务器身份验证后自动保持登录；不额外要求设备数量限制或设备管理。
•  每次客户端启动需要联网校验账号状态；账号停用时禁止访问，重新启用后原先有效登录的设备自动恢复，无须重新输入激活码。
•  管理员重置激活码后旧码立即失效，所有已登录设备必须重新输入新激活码激活。
•  员工在当前设备退出登录仅影响该设备，再次登录需重新输入激活码；账户页可查看与复制自己的激活码。
•  企业接口使用服务端验证的登录会话/令牌，不能仅凭激活码或客户端自报员工 ID 作为每次业务调用的授权依据。
验收重点  停用→重新启用恢复；重置激活码→全设备失效；单设备退出不影响其他设备；启动校验与后端接口验证均生效。
功能 02｜部门与员工管理（已确认）
•  后台支持部门、员工的新增、查看、编辑、删除；员工归属部门。
•  按部门配置模型、技能、连接器、专家等默认授权，并可针对单个员工独立增删调整；展示最终有效授权及其来源。
•  适配商场组织：一层至四层营运部门，以及跨楼层管理自营门店的「营运自营」等业务组织；不将实际组织结构硬编码。
•  细颗粒度商场数据权限与既有 LFClaw MCP 逻辑衔接；哪些楼层、门店、自营数据可访问，需检查现有 MCP 代码后再确定。
验收重点  部门继承和个人覆盖可解释；跨楼层自营组织能够正确表示；不预设未经确认的楼层行级规则。
功能 03｜模型管理（已确认）
•  管理员新增、查看、编辑、删除、启用、停用和测试模型；维护模型 ID、展示名、接口协议、Base URL、服务端 API Key 与计费参数。
•  模型类型按 DSH 实际适配能力逐步支持文本、视觉、图片、语音、视频、Embedding、Rerank；缓存价格、多模态单位与币种按供应商需要配置。
•  按部门、员工下发可用模型和默认模型；员工只可在聊天输入框内的模型下拉框切换已获授权模型，不可自配企业模型和企业 API Key。
•  企业模型调用统一经过 LFClaw 模型网关，记录员工、部门、模型、请求用量、可用 Token 与费用；不设计积分、额度或配额限制。
•  费用状态区分「服务商返回」「估算」「未获取」；以人民币等值汇总，同时保留原币种和汇率/换算依据，无法确定费用不记作 0。
•  员工个人 Cordis 插件直接调用个人第三方 AI 服务被允许，但不进入企业模型网关与企业费用统计。
验收重点  服务端不暴露企业 API Key；模型撤权立即拒绝新请求；价格估算口径可追溯；个人外部调用不混入企业账单。
功能 04｜技能管理（已确认）
•  企业技能通过 ZIP 上传；校验包结构并解析 SKILL.md；后台支持增删改查、启停、历史版本、回滚与部门/员工授权。
•  企业技能变更自动同步到员工客户端；运行中任务不因企业资源更新被任意打断。
•  员工可自行创建、安装、修改、删除个人技能；个人技能不影响企业技能；模型可自动选用技能，也允许用户主动选择。
•  管理员可查看员工个人技能清单元数据（名称、描述、版本、来源），不得查看个人技能正文或修改其内容。
•  同名企业/个人技能允许共存，界面明确标记来源；不建设技能调用次数和使用时长统计。
验收重点  异常 ZIP 被拒绝；技能版本回滚可用；企业更新不覆盖个人技能；管理员看不到个人技能正文。
功能 05｜连接器管理与权限（已确认）
•  将 MCP、第三方办公应用连接与企业自有 API 统一视作连接器；后台增删改查、启停、测试、发现工具与管理工具清单。
•  授权可按全员、部门、员工配置，支持连接器整体权限与连接器内工具级权限；客户端自动同步授权范围。
•  员工可对已获授权的企业连接器绑定自己的外部账号，但不得自行创建新的“企业连接器”；个人 Cordis 插件自由安装权另见功能 11。
•  优先使用成熟连接器；企业级服务建议由服务器集中托管，确需本机文件/应用能力时再部署本地执行插件。
•  管理员可以查看连接器与工具权限清单，不查看员工个人凭据或绑定后的实时状态；不额外建设连接器调用统计或平台级二次确认体系。
•  商场 MCP 请求采用可信服务端身份校验后取得员工身份及数据范围，拒绝客户端伪造 Header；具体店铺、楼层、自营行级权限待现有 MCP 源码核查。
验收重点  工具级权限生效、账号凭据不外泄、伪造员工 ID 无法越权、企业连接器与个人插件分类明确。
功能 06｜专家中心（已确认）
•  统一展示与管理 DSH 原生本地专家及阿里云百炼等外部 API 专家；企业专家由管理员创建、编辑、删除、启停和部门/员工授权，自动同步客户端。
•  DSH 原生专家采用对话式 AI 创建、编辑，不开发繁琐的高级表单；外部专家由管理员维护接入 API / 应用参数。
•  员工可创建、编辑、删除自己的个人专家；管理员不查看、不修改员工个人专家。
•  个人专家配置保存在 LFClaw 后端，可在本人多设备同步；个人插件/技能不跟随自动同步，缺失依赖时提示员工自行安装。
•  企业专家整体授权，其模型、工具与数据能力以专家预设范围为准；外部专家不强制套用每个员工的个人 MCP 数据范围，边界需由服务端/专家服务实际执行。
•  个人专家不能绕过员工本人原有权限；能拿到的数据以该专家可用工具与员工有效凭据为界。
•  统计专家模型用量与费用，外部服务无法提供的明示「未获取」；不做专家配额；不追加专家跨部门授权提示。
验收重点  企业专家与个人专家隔离；外部专家授权及实际数据边界一致；个人专家在另一设备出现时，依赖缺失提示清楚。
功能 07｜客户端发布更新（已确认）
•  仅交付 Windows x64 与 macOS Apple Silicon，独立版本号、独立安装包、独立发布；Windows 使用本地 Windows 环境构建，macOS 优先 GitHub Actions 构建。
•  客户端安装包存放阿里云 OSS，企业后台管理不同平台版本、安装包、更新说明、普通/强制更新、启用及发布记录。
•  客户端自动检查/下载新版本；普通更新由员工确认安装；强制更新在需要时阻止继续使用旧版本。
•  管理员可查看员工上报的客户端版本、操作系统、最近上报时间与更新状态（含离线）。
•  发布面向全员，不开发灰度、分批、按部门推送；正式全员发布前仍须完成内部测试。
•  更新必须保留本地聊天、工作文件和设置；企业级签名、macOS 公证、自建升级 Feed / OSS 发布路径在技术核查中落地。
•  DSH 上游版本只在兼容性通过后择优升级；保持 LFClaw 版本与底层 DSH 版本的清晰映射。
验收重点  Win / Mac 独立升级和回退、强更拦截、OSS 下载校验、安装后数据保留、升级失败可恢复。
功能 08｜定时任务（已确认）
•  使用 DSH 原生调度机制，员工在本机创建、查看、修改、删除、启停任务；只有客户端及 Host 运行期间本地执行。
•  不在 LFClaw 服务器执行员工任务；关机、客户端未运行时不保证按计划执行，恢复策略以实际 DSH 机制核查为准。
•  管理员后台只读查看任务负责人、任务名称、时间规则、启停状态、最后触发时间、最近同步时间及离线/过期快照。
•  客户端上报任务元数据快照；管理员不查看任务指令、执行结果或对应聊天，不远程修改员工任务。
验收重点  本机任务执行与离线恢复行为实测；后台只见元数据；本地任务失败通知符合功能 13。
功能 09｜客户端体验与会话分享（已确认）
•  简化 DSH 主界面：启动直接进入聊天；模型选择仅在输入框内，保留专家、技能、连接器、定时任务、会话、账号信息入口。
•  账号信息显示姓名、部门、个人激活码（查看/复制）、已授权模型/技能/连接器工具/专家以及退出登录。
•  本地个人会话支持正常的新增、查看、修改、删除及继续聊天。
•  发送人可从历史会话中选择完整聊天记录，包括最初上传的文件附件和 AI 输出文件，按员工检索、多选，跨部门分享。
•  会话分享数据临时存于既有 LFClaw 后端磁盘；默认保留 30 天、单份总量上限 50MB（聊天与文件合计），管理员可调整，过期自动清理；不使用 OSS、MinIO 或 P2P 作为会话分享存储。
•  接收人可查看分享来源、发送人、时间、标题，领取后在本机成为独立 DSH 新会话并可继续对话；原始内容与接收人新增内容保持清晰区分，发送人的会话不被改写。
•  历史内容可跨部门阅读；接收人后续调用 MCP 必须使用自己的有效权限。已领取到本地的会话不受服务端分享过期影响。
•  不额外设计专门的“再次分享/转发”和“取消分享”功能。
验收重点  完整附件、跨部门领取、本地独立继续、发送人记录不变、50MB 和 30 天、过期后不可再次下载。
功能 10｜知识库与个人记忆（部分确定，权限待定）
•  明确不自研知识库引擎，优先复用 WeKnora、阿里云百炼等现有平台，通过功能 05 连接器及适配工具接入。
•  本阶段不开发个人长期记忆，不独立建设知识库管理后台。
•  知识库权限究竟复用连接器授权还是需要独立授权，尚未确认；应先核查外部平台文档权限及现有 LFClaw MCP。
•  暂不假设所有知识库都有可用的文档/知识分区权限，更不能以“已连接知识库”推导“员工有权访问所有文档”。
待解决问题  WeKnora / 百炼接入形态、知识库索引与文档权限能力、员工身份映射、专家调用时的数据授权边界。
功能 11｜DSH 原生功能与插件管理（已确认）
•  尽量保留 DSH 原生工具、终端、网页搜索、子智能体、团队、创造模式及相关配置能力；客户端界面根据员工需求简化，不硬性移除底层能力。
•  管理员负责企业 Cordis 插件增删改查、启停、版本管理、授权、发布和自动同步；仅管理员可将插件作为企业资源发布。
•  所有员工都能使用创造模式、自行开发、安装、编辑、配置和删除个人插件；企业与个人插件可共存。
•  管理员只读查看个人插件的名称、版本、来源，不可修改或删除，也不查看个人插件内部内容。
•  企业插件优先于冲突的个人插件，个人插件不得覆盖企业插件；同名技能或专家以「企业 / 个人」来源区分。
•  企业插件自动下载，正在执行任务时不强行中断；空闲时安全应用更新，需要重启的插件在下一次启动生效。
•  员工可在个人插件中自行接入外部 AI API，此类调用不计企业账；企业 API Key 不下发给个人插件，企业模型接口仍由服务端控制。
说明  Cordis 插件属于可执行代码：服务端授权可保护企业接口，但不能据此承诺员工本地文件对第三方插件完全隔离。需通过安全告知与代码权限机制开展技术核查。
验收重点  企业与个人插件共存、热更/重启兼容、创造模式、管理员个人插件清单只读、企业权限无法被伪造。
功能 12｜企业后台系统管理（已确认）
•  只保留 1 个超级管理员账号，支持登录、退出、修改密码，管理全部后台功能；不开发多管理员与复杂角色权限。
•  密码忘记时，由拥有阿里云服务器管理权限的技术人员通过安全管理命令执行重置；不开发邮件/短信找回。
•  后台数据仅支持手动备份、下载与上传恢复；不做定时自动备份。备份需完整性验证；恢复前校验文件有效性及版本兼容并二次确认，尽量保护原数据。
•  备份范围包含服务端企业配置、员工与部门、授权、用量等必要数据；不包含员工电脑本地聊天及文件。
•  记录管理员重要操作日志：时间、类型、对象、非敏感变更；可查询过滤，不记录密码、API Key 和员工聊天正文。
•  提供简单服务器在线状态、CPU/内存/磁盘使用率、模型网关状态与最近错误信息；不建设复杂监控平台。
•  不开发独立“系统基础设置”页面；各业务配置仍放在所属模块。
验收重点  单管理员、命令行安全重置、备份可恢复且失败保护、操作日志脱敏、状态看板准确。
功能 13｜消息通知（已确认）
•  仅在 LFClaw 客户端内展示消息中心，显示未读数量，支持点击进入关联页面；不弹出 Windows/macOS 系统桌面通知。
•  通知包括会话分享、新客户端版本/强更、定时任务失败或需处理事件、需员工处理的本机异常；企业模型/技能/连接器/专家/插件更新静默同步。
•  消息保留最近 30 天，支持已读/未读、单条删除、全部清空，过期自动清理；删除消息不等于删除原始会话或任务。
•  会话分享通知及已读状态在员工设备之间同步；客户端版本、定时任务、本机异常通知仅对应设备本地展示。
•  分享文件与通知分别计期，删除通知不删除分享；分享过期而通知仍保留时显示已过期，不允许重新领取文件。
•  定时任务成功不默认产生通知，结果在任务页面查看。
验收重点  30 天自动清理、跨设备分享通知状态、其他通知本地化、失效分享正确提示。
功能 14｜故障诊断（已取消）
明确取消独立故障诊断模块：不开发自动诊断、一键检测、诊断日志上传、故障管理后台。保留 DSH / 基础运行环境原有的错误提示及必要技术日志，不将这些基础能力扩展为产品新模块。
功能 15｜本地数据管理（已确认）
•  原样复用 DSH 原生本地聊天、工作文件、设置与数据存储能力，不额外开发备份、导出、恢复或设备迁移系统。
•  同一员工在不同电脑上的本地聊天记录及工作文件相互独立，不云端自动同步。
•  正常客户端升级应保留本地会话、工作文件、个人设置；电脑更换/重装不额外提供迁移功能。
•  不改变个人专家配置跨设备同步、企业技能与插件自动同步、会话分享与消息中心的已确认例外规则。
•  个人技能及个人 Cordis 插件不额外跨设备同步；新设备的个人专家遇到依赖缺失时给出安装提示。
验收重点  正常升级保留数据；多设备会话互不覆盖；个人专家配置同步但不偷偷同步个人插件。
功能 16｜IM 渠道接入（已确认）
•  支持个人微信 ClawBot 与飞书；微信由员工在客户端扫码绑定，飞书由员工自行配置并绑定自己的飞书应用。
•  员工个人独立管理 IM 渠道，不开发企业统一飞书机器人、集中管理 IM 应用或服务器侧统一消息中转系统。
•  微信/飞书消息交给该员工自己电脑上正在运行的 LFClaw / DSH Agent 执行；员工电脑关机或客户端未运行则不能继续远程执行。
•  仅支持私聊，不设计群聊或群权限；按个人绑定机制识别发送者，优先使用成熟插件的原生能力，不追加复杂 IM 身份管理。
•  IM 能使用员工已有授权的企业模型、技能、专家、连接器等完整 AI 能力；具体图片/附件/音视频消息格式以实际渠道与插件能力为准。
•  IM 会话保存到对应电脑的 LFClaw 会话列表，支持回到桌面查看、继续；不自动将本地会话同步到别的电脑。
•  优先核查 DSH 社区渠道插件的微信扫码、飞书应用配置与会话映射；腾讯官方 openclaw-weixin 是 OpenClaw 插件，不能假定直接安装在 DSH 中。
验收重点  个人扫码/应用绑定、本地离线限制、IM↔桌面同会话、私聊与服务端企业授权、Windows/macOS 真机接入。

07｜关键验收清单与非目标
7.1 核心端到端验收场景
AT-01  新员工安装客户端，仅输入激活码即可进入聊天；不需要手填服务器地址或企业 API Key。
AT-02  同员工多台电脑登录；其中一台主动退出只影响本机；管理员停用后全部设备新请求被拒，启用后有效设备恢复。
AT-03  管理员重置激活码后旧凭据无法继续使用，所有设备必须重新激活。
AT-04  管理员调整部门和个人模型/连接器权限后，服务端立即校验、客户端在线刷新；伪造员工 Header 无法越权。
AT-05  员工在输入框选择已授权模型，企业网关记录来源、Token/费用状态；个人第三方 API 调用不入企业账。
AT-06  企业技能/插件自动分发及安全更新；员工个人插件与个人技能互不覆盖，创造模式可用。
AT-07  企业专家和个人专家分开；个人专家跨设备有配置，新电脑缺失个人依赖时明确提示。
AT-08  本地定时任务执行，管理员只能看元数据；失败通知仅显示在执行任务的电脑。
AT-09  跨部门分享含原始附件和 AI 文件的完整会话；接收人领取后能独立继续；后续数据工具按接收方权限。
AT-10  分享与通知各自 30 天清理；过期分享无法重新领取，本地已保存会话可以继续。
AT-11  员工通过个人微信 ClawBot 扫码/飞书应用配置，在电脑运行期间私聊调用 LFClaw；历史出现在本机桌面会话。
AT-12  Windows / Mac 独立版本发布、强更与数据保留；后端手动备份校验和恢复成功。

事项 | 边界 / 风险承认
第三方个人插件 | 员工可自由安装执行本地代码；企业接口不信任插件，但无法保证其读取不了本地文件，正式上架应明确风险。
专家数据范围 | 企业专家可能使用高于单个员工的预设数据范围；用户确认不增授权提示，管理员需对发布范围负责。
分享跨部门 | 发送人可分享自己已有的历史数据；接收人可读已分享历史内容，但新数据调用按接收人权限。
分享存储空间 | 已确认不做专项磁盘空间保护，存在异常大量分享占满磁盘的运维风险；基础系统磁盘监测仍由功能 12 提供。
服务器故障与备份 | 只有管理员手动备份，不保证每次故障都有最新恢复点；需建立人工运维操作制度，但不增加自动备份产品功能。
IM 渠道可用性 | 员工电脑或 DSH Host 不运行则不能处理消息；第三方渠道平台本身变动也可能需要插件更新。
DSH 上游迭代 | 官方 Developer Preview 可能破坏兼容性；不能无测试直接升级最新版。
