# LFClaw 企业服务

[English](README.md) | 中文

<a id="lfclaw-企业服务"></a>

仓库 Host 构建通过 `tsconfig.build.json` 引用服务端类型声明，输出位于 `lib/types`；服务端保留自己的 NodeNext 编译配置，客户端编译不加载服务端测试。

员工独立绑定的企业 OAuth 支持桌面客户端本机回调，企业服务可保持现有公网 HTTP IP。客户端通过员工身份调用 `oauth-loopback`，提供临时 `127.0.0.1` 回调；浏览器返回后再用同一身份调用 `oauth-complete`。服务端校验员工、连接器、配置、一次性 state 与 PKCE，再交换授权码、发现工具并保存该员工凭证。客户端不保存企业 OAuth 令牌，所有工具调用仍经过企业服务端。

企业服务作为 DSH Web profile 的 Cordis 插件启动，接口前缀为 `/lfclaw/api`。管理页面的开发代理连接 DSH Web；数据默认存于本目录 `data/`，该目录已排除 Git 跟踪。

## 会话分享与通知

<a id="会话分享与通知"></a>

管理员在“消息通知”发布企业公告后，服务端保存标题、正文和发布时间。已登录员工通过 `GET /api/employee/announcements` 接收；`POST /api/employee/announcements` 以 `{ "id": "公告 ID", "action": "read|unread|delete" }` 更新本人状态，以 `{ "id": "all", "action": "clear" }` 清空本人公告。已读和删除状态按员工保存在数据库，其他员工及管理员历史记录不受影响。旧公告也会出现在员工列表中。客户端在“分享与消息”展示公告并汇总未读数；本功能不发送系统桌面通知。

管理员可调用 `POST /api/admin/notifications/:id/revoke` 撤回历史公告。服务端在原公告上保存 `revokedAt`，管理历史和操作日志保留；重复撤回返回同一记录，不重复写日志。撤回后，员工公告列表与 `/api/employee/me` 均不再返回该公告，员工也不能再修改它的已读状态。已打开的客户端在下一次收件箱轮询或手动刷新后移除公告，并重新计算未读数；离线客户端重新连接后只会收到未撤回公告。旧数据没有 `revokedAt` 时仍视为有效公告。

管理员可调用 `DELETE /api/admin/notifications/:id` 删除已撤回公告；未撤回时返回 409，必须先撤回。删除会从服务端公告记录和管理端历史中移除该项，保留不含公告正文的操作日志以便核对。重复删除返回 404；既有备份不随删除改写。

员工接口 `/api/employee/session-shares` 接收完整会话和文件包，`/employees` 只返回有效员工姓名及部门，支持跨部门检索；`/policy` 返回当前上限。`/notices` 读取或修改当前员工的已读、未读、单条删除及全部清空状态，状态由服务器在设备之间共享。`/:id/download` 只允许明确指定的接收人在有效期内下载；停用、重置激活码和退出后的凭据不能下载。

分享存于 `dataDirectory/session-shares`，不进入企业员工数据库，也不使用对象存储。`index.json` 的版本 1 保存策略、分享元数据及接收人通知；以随机 UUID 命名的 JSON 文件保存会话与附件数据。默认保留 30 天、聊天与原始文件字节合计上限 50MB；传输的 base64 膨胀另设有界 HTTP 限制。文件长度和 SHA-256 在每次下载时校验，损坏时停止下载并返回错误。

管理员在“消息通知”的“会话分享”区域设置新分享的保留天数及大小；对应 `GET/PUT /api/admin/session-sharing`，范围为 1–365 天和 1KB–1GB。调整策略不改变已发分享的到期时间。`shareCleanupIntervalMs` 控制 Cordis 插件持有的清理计时器，默认 60000 毫秒，最小 1000 毫秒；卸载时停止。启动、读取通知和下载也会清理过期文件。分享通知独立保留 30 天，删除通知不影响文件，文件过期但通知仍在时显示已过期。已领取的本地会话不受服务端清理影响。

## 本地启动

<a id="本地启动"></a>

先在仓库根目录安装依赖并设置 `LFCLAW_ADMIN_PASSWORD`（首次初始化至少 12 个字符）。建议设置独立的 `LFCLAW_DATA_DIR`；管理页面通过 `LFCLAW_DSH_URL` 指向 DSH Web。

管理员登录和员工激活各自按来源地址限制失败次数。`cordis.patch.yml` 中的 `authWindowMs`、`loginMaxFailures`、`activationMaxFailures` 控制时间窗口与阈值；超限返回 HTTP 429 和 `Retry-After`，成功后清除该地址对应接口的失败计数。

同一配置中的 `adminSessionTtlMs` 和 `employeeSessionTtlMs` 分别控制管理员与员工令牌有效期。会话摘要跨服务重启保留；旧会话文件在首次启动时补入到期时间。过期令牌会被拒绝并从会话文件移除。

```sh
pnpm install
pnpm dsh web --patch ./LFClaw/02-管理端/server/cordis.patch.yml --port 39811 --no-open
```

管理 Web 在 `LFClaw/02-管理端/admin-web` 执行 `pnpm dev --host 127.0.0.1 --port 5173`。管理员首次账号为 `admin`，密码以首次启动时的环境变量为准。后续通过管理页面修改密码，旧管理员会话随即失效。

## 权限接口

<a id="权限接口"></a>

### 通用连接器认证

<a id="通用连接器认证"></a>

连接器 `authentication` 包含 `type`（`none`、`token`、`fields`、`oauth`）和 `owner`（`enterprise` 或 `employee`）。字段声明 `key`、`label`、`required`、`secret`、`target`、`name` 和 `prefix`，映射到 stdio 环境变量或远程 HTTP Header；值通过独立账号接口保存，不写进公开字段描述。旧 `employeeCredentials: wechat-mp` 自动按 AppID、AppSecret 字段解释，原绑定继续有效。商场连接器保留原公共认证配置及业务权限检查。

管理员操作 `/api/admin/connectors/:id/credentials`，员工操作 `/api/employee/connectors/:id/credentials`。GET 返回状态和配置摘要，POST 接受 `operation`（`save`、`oauth`、`remove`）及 GET 返回的 `configuration`；`save` 另带 `values`。身份来自当前登录令牌，客户端不能指定归属人。空值保留当前配置下原值，更换非密钥账号字段时须重填密钥。保存前只检查 MCP 连接和工具发现，不保证远程业务操作已获准；失败保留原账号。

OAuth 复用 MCP SDK 的发现、动态客户端注册、授权码交换和 PKCE；不支持动态注册的服务可设置公开客户端 `clientId`、`issuer`，可选 `scopes`。回调状态十分钟过期、只消费一次，提交前重新校验发起者、配置、分配范围及连接器状态。令牌在服务要求时刷新；无法续期时要求重新授权。解除连接删除本地授权记录并拒绝迟到结果，不承诺撤销已经发生的远程操作或自动撤回服务商网页里的授权。

桌面员工本机回调不依赖 `LFCLAW_OAUTH_CALLBACK_URL`，需要配套更新客户端，并由服务商支持 loopback redirect。管理员共用账号和旧客户端仍使用服务端回调：设置 `LFCLAW_OAUTH_CALLBACK_URL` 为浏览器可达的 HTTPS 地址并转发到 `/lfclaw/api/connectors/oauth/callback`；未配置时返回 `503 OAUTH_CALLBACK_UNAVAILABLE`。开发 patch 默认本机回调，仅适合同机浏览器。`oauthFlowTtlMs` 控制等待时间。OAuth 只用于 HTTP 传输；特殊扫码、私有签名和要求私密客户端密钥的流程仍需适配。

私有凭据存放在 `connectorAccounts`，不会进入管理数据响应或下载备份；原始文件须由运维保护。员工 stdio 的 `DATA_DIR`、用户目录和常见缓存目录按账号版本隔离，这不构成操作系统进程沙箱。修改认证目标、字段映射或连接配置后须重新绑定。使用本次账号目录格式时，员工客户端和企业服务须同步更新。

### 商场楼层权限与即时失效

<a id="商场楼层权限与即时失效"></a>

员工身份来自企业令牌；楼层权限每次从服务端读取，仅使用员工个人多选配置；空数组、缺少配置或格式错误均拒绝全部商场数据，不从部门或上级部门继承。查询参数中的 `openId`、`appId`、`appSecret` 由服务端清空，使用 MCP 现有普通调用方式；楼层参数由企业网关校验和限定，员工不能通过参数或提示词提升权限。楼层和区域多范围请求先取请求与员工授权的交集，仅查询有权限的范围，并在结果中注明未授权楼层无法获取。参数无效、请求范围完全未授权或工具本身未授权时返回 403。

按 `E:/code/lf-mcp-server2` 当前查询实现，部分楼层权限只开放 `getFloorDimensionData`、`getRegionDimensionData`、`getShopDimensionData`。拥有全部五项权限时，所有已启用且已分配的工具均可调用，包括淘气堡和未知工具；工具开关及连接器授权仍生效。部分权限的楼层、区域请求按单楼层拆分，店铺查询缺省楼层时按全部已授权楼层拆分，防止上游附带全场汇总或因缺少楼层参数查询全场。任一子请求失败不返回已完成的部分数据。

这三个查询工具的成功 JSON 响应中，`info` 权限说明使用当前员工授权范围，避免上游普通身份返回的全场权限提示误导模型；`data` 业务结果不变，失败响应保持原值。商场连接器授权和楼层授权不会自动启用工具，管理员须在连接器管理中测试获取工具并勾选所需工具。

非商场连接器的已发现工具自动可用，不要求管理员逐个授权，历史工具记录的 `allowed` 值也不限制调用；未知工具仍被拒绝，连接器启用状态、员工状态和分配范围继续校验。微信公众号连接器选择员工账号模式后，员工在客户端保存自己的 AppID、AppSecret 并完成工具发现即可使用，无需管理员再授权工具。凭据按员工保存，运行数据目录按连接器、员工和账号绑定版本分别建立；账号解除或配置变更会使旧调用失效。客户端必须加载包含账号表单和 Host 账号接口的构建。

`GET /api/employee/connector-catalog` 返回当前连接器、有效楼层和修订摘要，携带相同 `revision` 时等待授权变化或 `mcpTimeoutMs` 到期。管理操作提交后唤醒受影响的客户端，同时中断在途发现和调用；即使随后恢复相同权限，旧请求也不会下发结果。客户端移除旧工具、丢弃迟到结果并刷新范围，同步失败清除旧授权后重试。无需重新登录。该通知依赖单进程 `JsonStore`，不支持多进程直接共写文件或绕过管理接口编辑数据库。

无需配置 `LFCLAW_MCP_PERMISSION_SECRET` 或 Java 的 `lfclaw.permission.secret`。网关不发送权限签名 Header，也不进入 Java 的企业签名身份分支。旧部署中的 `mcpSecretEnv` 配置兼容读取但不再使用；MCP 源码与配置均无需修改。

楼层限制适用于经 LFClaw 企业服务发起的调用；它不改变 MCP 对其他客户端的访问行为。个人连接器不能使用已配置商场连接器的同源地址绕过企业网关。已有会话中的历史数据不会因撤权被擦除，保护适用于后续调用及尚未返回的结果。

### 资源与管理接口

<a id="资源与管理接口"></a>

连接器支持 Streamable HTTP、旧版 SSE 和 stdio。远程连接器使用服务地址与自定义请求 Header；Header 值在管理接口中被遮盖，地址不变时编辑留空沿用已保存的值，改动地址后必须重新填写，避免把旧凭据发给新服务。现有商场连接器继续使用 SSE，楼层参数由企业网关按员工权限限制。图标可上传 2MB 以内的 PNG/JPG，未上传时客户端显示默认连接图标。

管理员配置 stdio 时保存 `command`、字符串数组 `args` 和字符串字典 `env`；命令由企业服务器运行，员工只通过企业网关调用已授权工具。使用 `npx` 须在服务器安装 Node.js 并确保服务进程的 PATH 能找到它；`DATA_DIR` 等路径对应服务器文件系统。每次测试、工具发现或调用建立独立进程，操作完成、失败、超时或撤权后关闭连接。需要跨调用持久化的 MCP 应使用专用数据目录。

stdio 使用 SDK 的基础环境变量白名单并合并管理员配置，不继承企业服务的全部环境变量，进程 stderr 不写入企业服务日志。`env` 值在管理接口中置空，员工目录不包含命令、参数或环境变量；管理日志只记录字段名称。命令和参数不变时空字符串保留已保存的值，删除键移除变量，修改命令或参数后必须重新填写值。切换传输时清除另一种传输的连接字段。服务端校验参数类型、环境变量名称和长度；测试只发现工具，不自动授权。凭据应放入环境变量，不要放入会在管理页面回显的命令或参数。

连接器记录可设置布尔字段 `showToolsInClient`，默认 `true`。员工资源接口仍返回已授权连接器及该展示标记；桌面连接器中心始终展示已授权连接器，仅在标记为 `true` 时展示其工具名称、数量和说明。旧字段 `showInClient` 仅用于迁移已有记录。此标记不改变员工、连接器、工具及商场数据权限，也不阻止已授权工具由智能体调用。

员工生效权限接口为专家资源额外返回 `expertKind`（`expert` 或 `team`），供管理页分别展示专家与专家团；两者仍使用同一专家授权集合。

管理员使用 `POST /api/admin/login` 获取令牌，后续请求带 `Authorization: Bearer <token>`。`GET /api/admin/employees/:id/effective` 返回员工对模型、技能、连接器、专家的生效结果与来源。`PUT /api/admin/permissions/:collection/:resourceId/:employeeId` 接受 `{"decision":"allow|deny|inherit"}`；`inherit` 删除个人覆盖，恢复部门或原资源范围规则。停用资源始终不可用；个人拒绝优先于个人允许，部门授权向下继承。每次改动写入操作日志。

商场 MCP 的业务数据权限另设为五项：`operation.floor.1` 至 `operation.floor.4`、`operation.self_operated`。`GET /api/admin/employees/:id/mcp-permissions` 返回员工当前生效项，不再返回继承模式；`PUT` 同一路径仅接受 `{"permissions":[...]}`，支持五项标识的任意唯一组合，空数组表示无商场数据权限，`null` 返回 400。部门楼层和自营字段不参与数据授权。写入时校验标识、持久保存并记录操作；编辑员工基本资料不会覆盖该设置。员工调用商场 MCP 时服务端重新读取权限并限定查询参数，仍须先具有连接器及工具访问权。MCP 服务源码没有改动。

员工以激活码调用 `POST /api/employee/activate`，`GET /api/employee/me` 只返回本人当前可用的资源；模型调用和商场 MCP 工具调用也在服务端重新校验当前授权，因此撤权后无需员工重新登录即可生效。

企业专家由管理员创建并分配给全员、部门或员工。百炼智能体填写已发布应用的 App ID、可选 Workspace ID 和服务端保存的 API Key；Dify Chatbot / Chatflow 填写以 `/v1` 结尾的 HTTPS API 基础地址、应用 API Key 和可选输入变量 JSON；WeKnora Agent 填写以 `/api/v1` 结尾的 API 基础地址、Agent ID 和具备 `chat` 权限的空间 API Key。WeKnora 接受 HTTP 和 HTTPS API 地址；HTTP 会明文传输空间 API Key，推荐在可用时使用 HTTPS。员工目录不返回密钥。已授权远程专家可通过 `POST /api/employee/experts/prepare` 返回远程调用标识，再由本机会话工具调用 `POST /api/employee/experts/:id/chat`；企业服务在每次调用时重新鉴权。Dify 调用先检查应用类型，再以当前员工标识、阻塞式 `chat-messages` 和返回的 `conversation_id` 继续对话；Agent、旧版 Agent 与 Workflow 不支持此接口。WeKnora 调用先创建会话，再向 `agent-chat` 发送问题，只汇总 SSE `answer` 事件并等待 `complete`；返回给客户端的会话标识按专家及员工签名，拒绝跨员工续聊。WeKnora 调用共用 `expertTimeoutMs` 的总等待时间，本地配置为 180 秒；超时返回 HTTP 504 和 `EXPERT_TIMEOUT`，本次不返回未完成的答复，远程会话可能仍在处理。其他外部平台需要对应的服务端对话适配器。专家团仅在本人同时获授权全部成员时可见。员工个人专家走独立接口：`POST /api/employee/personal-experts/draft` 使用本人可用的企业默认模型生成草稿，员工确认后再用 `POST /api/employee/personal-experts` 保存；本人可读取、修改、删除，其他员工无权操作，管理员数据接口不展示个人专家。

连接器写入时分配范围只接受全员、有效部门或有效员工；模型、技能、连接器和专家支持 `scope: none`（都不授权），其 `scopeTarget` 必须为空，优先于个人覆盖拒绝所有员工访问。指定部门或员工的非空目标必须存在。员工可见的连接器及可调用工具在服务端按范围、个人覆盖与工具启用状态计算。列表里的工具开关是该连接器的全局可用工具清单；商场 MCP 的五项数据权限由员工详情另行设置。

模型可设置一个企业默认项；新建或设为默认时，服务端会清除其他模型的默认标记。编辑模型保留原有部门或员工授权范围。管理页的“名称”用于展示，“上游模型 ID”用于实际请求；旧记录没有该字段时沿用名称，以便迁移。

模型可设置每百万输入与输出 Token 单价及三字母币种，两项单价须同时提供。服务端在调用时保存计价快照；上游返回有效 Token 用量且价格完整时计算六位小数费用，否则记为“未获取”。总览只汇总本月同币种且全部可计价的记录，不把未知费用当作零。

连接器的 `mallDataPermissions` 开关决定是否使用员工商场楼层权限，与名称、部署地址、传输方式及自定义 Header 独立。默认关闭；同一企业只允许一个连接器开启。旧记录的 `authMode: mall` 按开启读取，下次保存写入显式开关。普通远程服务关闭时执行连接器和工具授权；已识别为 DBC MCP Server 的商场服务若关闭此开关，员工调用会被拒绝。开启时按员工楼层权限决定工具与查询范围。SSE 使用现有 `/sse` 或 `/sse2` 入口，Streamable HTTP 使用配置的服务地址；两种传输均保留服务端自定义 Header。

桌面 Host 通过已认证的 `POST /api/employee/personal-connectors/check` 检查个人远程 MCP 地址。与任意已开启商场数据权限的企业连接器同源时返回 403，员工须改用企业连接器；无效地址返回 400。接口不接收 Header 或本地环境变量，不保存个人配置，也不替代远端服务自身认证。

首次开启或修改已开启连接器的地址、传输方式、Header、启动命令、参数或环境变量时，保存前只读连接并读取工具目录；失败保留原配置并返回 `MCP_PERMISSION_UNVERIFIED`。改名和调整工具授权不触发连接验证。工具发现不会调用业务数据工具，也不自动授予新工具权限。

## 数据与验证

<a id="数据与验证"></a>

管理员总览通过 `GET /api/admin/data` 返回即时计算的 `dashboardTrend` 与 `recentActivities`。趋势覆盖含当天的最近七个 UTC 自然日，按网关接受的员工模型请求计次，包含成功、失败与处理中请求；`conversations` 字段对应界面的“模型调用次数”，不代表本地聊天会话数。`tokens` 汇总已获取的非负整数 Token，`missingTokenCalls` 单独记录未知用量，活跃员工按日期和员工 ID 去重。未获授权而被拒绝的请求及管理员模型测试不纳入员工调用统计，不采集员工聊天正文。

管理员 `GET /api/admin/usage` 按需汇总模型网关用量；可选 `from`、`to` 为包含端点的 UTC 日期（`YYYY-MM-DD`），`employeeId`、`modelId` 可交叉筛选。响应包含按员工、按模型的汇总和总计，统计调用次数、已取得的输入/输出/总 Token，以及任一 Token 字段缺失的调用次数；已删除员工或模型使用原 ID 显示。错误日期和倒置区间返回 400，未授权访问返回 401。`GET /api/admin/data` 只返回汇总后的本月费用状态，不传输原始 `modelUsage` 列表；报表查询不在员工模型调用流程执行。历史用量仍在服务端 JSON 数据文件中，报表查询会按需读取和扫描该文件。

最新动态按操作日志时间倒序返回最多二十条，包含资源与权限修改、激活码重置、首页文案修改、通知发布及手动备份操作；历史数据仅展示已保存的日志，不补造历史操作。动态只返回时间、标识、类型和摘要。持久化记录格式错误时接口返回存储错误并保留原文件，不返回伪造的空统计。统计不写回数据库，服务重启后从原始记录重新计算。

新增、修改和删除操作的摘要保存操作时的资源类型与名称，删除资源后仍可直接阅读。修改摘要列出更名、启停及变更字段；密钥、认证 Header、接口配置等仅记录字段名称，不保存配置值。重复保存说明展示配置未变化。动态按资源类型分类；旧日志从操作类型恢复新增、修改或删除语义，已丢失的名称及修改明细明确标为未记录，不改写旧日志。

企业技能上传的 ZIP 必须包含唯一最外层 `SKILL.md` 作为主入口，其目录内允许附带子技能的 `SKILL.md`。并列主入口及主目录之外的文件会被拒绝；主入口 YAML 元数据需要非空 `description`。上传接口返回提取的描述；新增或编辑技能时，服务端从已上传的 ZIP 再次读取并保存该描述，管理员页面和员工资源接口使用保存后的值。技能名称由管理员填写；新建版本为 `1`，更换 ZIP 后递增，单纯改名或启停不递增。`GET /api/admin/skills/:id/versions` 返回历史版本，`POST /api/admin/skills/:id/rollback` 以 `{"revision":1}` 选择旧修订；回退前重读并校验旧 ZIP，成功后以更高修订号发布，不覆盖历史。旧数据没有历史记录时只能从当前版本开始补记。手动备份包含当前与历史技能 ZIP。`GET /api/employee/me` 向有权限的员工返回技能版本与 ZIP 的 SHA-256；`GET /api/employee/skills/:id/download` 仅下载当前授权且启用的最新版，支持 ETag 条件请求。员工桌面端由 ui-enterprise-skills 插件负责下载、校验与本地缓存，实际读取仍检查当前授权。

业务数据保存在 `LFCLAW_DATA_DIR/db.json`（未设置该变量时为本目录 `data/db.json`），管理员身份保存在同目录 `admin-auth.json`，备份与技能附件分别保存在 `backups/` 和 `skills/`。新增或修改部门、员工、模型、技能、连接器、专家，以及发布通知，均在服务端保存成功后才向管理页返回成功；页面刷新和服务重启会重新读取这些文件。关闭浏览器后可能需要重新登录，但业务数据不会因此清空。切换 `LFCLAW_DATA_DIR` 会看到另一套数据；版本发布入口尚未开放。管理员下载的手动备份包含模型用量与已引用的技能附件，但排除员工私人专家；历史归档下载时也重新校验并剔除私人专家。恢复企业备份时保留当前私人专家，不读取归档里的私人专家。服务器迁移时须由运维单独保护和迁移原始 `db.json` 才能保留个人配置。恢复前先校验数据库与归档，恢复时另建安全备份，恢复后的备份列表仅保留这份安全备份，避免出现没有 ZIP 文件的旧记录。勿将这些文件提交到仓库。可运行 `pnpm --filter @deepseek-ai/lfclaw-admin-server run test` 和 `pnpm --filter @deepseek-ai/lfclaw-admin-server run typecheck` 检查服务端。

管理员可调用 `DELETE /api/admin/backups/:id` 删除单条备份。接口先将归档临时移开，再移除记录并删除归档；若删除失败，会尝试恢复记录和文件并报告失败。文件已缺失的旧记录仍可删除。删除后该备份无法下载或恢复，操作写入管理员日志。

桌面通过 `POST /api/employee/v1/chat/completions` 使用 OpenAI 兼容协议调用企业授权模型；请求的 `model` 是企业资源 ID，服务端解析实际模型标识和密钥，并在每次调用时重新验证员工与资源授权。支持工具定义、工具调用消息和用量统计；`stream=true` 实时转发上游 SSE，保留文本、思考和工具参数分片，结束后记录用量；缺少结束标记或上游错误按失败处理。部署配置 `modelTimeoutMs` 控制非流式完整响应时限与流式数据等待时限，当前为 120 秒；超时返回 MODEL_TIMEOUT，员工停止请求或断开连接会中止上游。旧 `POST /api/employee/chat/completions` 继续接受 `modelId`。

技能发布与桌面安装共用 ZIP 校验器，拒绝非法名称、空正文、调用标志类型错误、歧义入口、不安全路径及重复目录项；默认安全上限为 ZIP 32MiB、解压 64MiB、20,000 项。管理端支持图标上传、更换及移除，图片限 2MiB PNG/JPG，并可编辑发布版本。

POST /api/employee/personal-skills/report 接收本人当前设备的完整个人技能元数据快照；服务器只接受名称、简介、版本、个人来源、启停状态，并校验请求员工与认证身份一致。正文、脚本、附件及本机路径不在协议内。GET /api/admin/personal-skills 提供按员工、设备和更新时间分组的只读清单，员工令牌不能读取此管理员接口。设备离线或同步失败时清单可能滞后，界面明确显示上报时间。旧数据库缺少 personalSkillReports 时初始化为空，不改写个人技能正文。

管理 Web 开发代理默认连接 `http://127.0.0.1:39811`，通过 LFCLAW_DSH_URL 覆盖。网络错误与账号密码错误分别展示，登录按钮在请求期间禁用。

公开接口 `GET /branding` 返回首页口号、标签及显示开关，不返回员工资料或凭据。管理员通过 `GET/PUT /admin/branding` 修改；口号为 1–40 字，标签最多 12 字，均为单行，显示标签时文字不能为空。配置保存在数据库 branding 字段并随手动备份恢复；旧数据缺少该字段时使用“让想法落地，让工作轻松”和“预览版”。无效配置拒绝读取或保存，修改记入操作日志。

## 专家中心

<a id="专家中心"></a>

企业专家可声明 `skillIds`、`connectorIds` 和 `quickPrompts`；管理员保存时校验依赖标识存在且无重复，示例问题最多三个、每个不超过 300 字。员工个人专家接受相同扩展字段，另以 `kind: team` 和 `memberIds` 保存本人专家团；未声明 `kind` 的旧记录按单专家处理。新增字段保存在现有 JSON 记录，不改变 DSH Session 格式。

`POST /api/employee/experts/prepare` 接受 `owner: enterprise | personal` 和 `id`，仅当前员工可调用。服务端重新检查专家归属、成员授权及全部成员所需的技能和连接器授权，返回不含凭据的名称、指令、成员和依赖清单。失败返回 HTTP 409 与 `EXPERT_NOT_READY`；管理员令牌不能用于员工准备接口。个人专家团成员只引用本人单专家，企业专家团成员只引用企业单专家。支持的外部服务专家由准备接口返回远程调用标识，不在本机执行其工作指令。

准备接口只读取当前配置，不执行任务、不保存聊天正文，也不授予新权限。员工客户端接着检查本机资源是否可用，并生成等待发送的普通会话草稿；百炼和 Dify 专家草稿要求模型调用企业专家工具取得真实答复，专家团任务草稿要求通过子代理工具委派真实成员任务。后续管理员撤权仍由各项工具与模型调用实时执行，不因已生成草稿而保留旧权限。

模型管理可逐模型设置 `contextWindow`（上下文窗口）和 `maxTokens`（单次最大输出 token 数），两者为正安全整数且输出不得超过上下文窗口。旧模型未设置时保留 32768 / 8192；管理员应按实际模型能力编辑保存。员工目录返回容量，网关以模型的 `maxTokens` 作为默认值及上限，允许请求使用更小值，非法请求返回 400。思考模式可保持供应商默认值，或在支持 `enable_thinking` 的 OpenAI 兼容模型上明确开启或关闭；服务端保存该选择，并只在明确配置时向上游发送该字段。供应商不支持该参数时应保持默认值。

个人专家对话修改通过 "GET /api/employee/personal-experts/:id" 读取完整配置与修订摘要；更新可携带 "expectedRevision"，摘要过期时返回 HTTP 409 与 "EXPERT_CHANGED"，保留较新的配置。员工端的管理技能始终携带修订摘要修改原记录。创建和修改时，成员必须是本人单专家，技能与连接器必须是当前已授权资源。

管理员可调用 `POST /api/admin/experts/import`，提交 `definition`、`preview`、`scope`、`scopeTarget`、`enabled` 和可选 `targetId`。预览只解析校验，不写库；发布在单次存储更新中保存根专家与全部新增成员。原创来源可省略或使用 `original`，已有存储来源标识继续兼容。接口也接受 WorkBuddy 1.0 单专家 JSON 导出包，从 `manifest` 和 `agent.content` 提取角色定义，预览返回 `migration` 提示；导出包内的本机路径、技能文件和二进制资源不会保存或授权，需在技能中心单独迁移。嵌入成员的 ID 会重映射，根专家更新保留 `targetId`；不自动删除旧成员。参数中的技能和连接器必须存在，发布不额外授予员工权限。当前专家团只支持原创成员。接口拒绝无效成员、嵌套专家团、外部 API 来源参数和错误发布范围，不留下部分导入记录。

`POST /api/employee/personal-expert-teams` 为当前员工整组创建个人专家团。请求含完整 `team` 和 `newMembers: [{key, definition}]`；`team.memberIds` 按顺序填本人已有单专家 ID 或 `new:key`。新成员 key 在请求内唯一，且必须被引用。所有成员、工作指令和实时能力授权在同次存储更新中校验，全部通过后一起保存；失败不会创建部分成员。已有成员不修改，新成员和团使用服务端生成的 ID；响应返回 `{team, members}`，其中 members 仅含新增成员。网络中断导致结果未知时先查询本人列表核对，不自动重试创建。该接口仅支持新建，已有配置修改继续使用带修订摘要的个人专家接口。

模型网关的 `modelTimeoutMs` 对非流式请求限制完整响应时间，对 SSE 请求限制首个数据块及相邻数据块之间的等待时间；持续收到上游数据时重新计时，不再按总时长中止仍在生成的回答。请求完成和失败均清理计时器，客户端取消仍中止上游请求。

技能上传与历史版本读取使用 `skillArchiveLimits`，默认限制压缩包 32MiB、解压总量 64MiB、20,000 个 ZIP 条目；两份服务端部署配置显式设置这些值。员工端的 `maxArchiveBytes`、`maxUnpackedBytes`、`maxFiles` 与之保持一致。超限上传会被拒绝，不会保存技能包。
